## New defects found

### QC-R2-001 — Validation failures return HTTP 500

Cases: `AUTH-005`, `USR-004`, `CRS-006`, `ASN-002`
Severity recommendation: High

Malformed Zod input is passed to the general error handler without a client-error status. Invalid login, user, section, and assignment payloads therefore return HTTP 500 instead of a stable 400/422 validation envelope.

### QC-R2-002 — Public verification enumerates partial email fragments

Case: `PUB-003`
Severity recommendation: High

Anonymous verification with `q=marcus` returned `match: true`. The public endpoint accepts partial email fragments even though its UI/API description asks for a student number.

### QC-R2-003 — Spoofed localhost origin is accepted by CORS

Case: `SEC-001`
Severity recommendation: High

The API reflected `http://localhost.attacker.example` as an allowed origin because the origin check performs substring matching for `localhost`.

### QC-R2-004 — People search is unintentionally case-sensitive

Case: `SRCH-002`
Severity recommendation: Medium

Searching `aUtOmAtIoN` failed to return people named `Automation ...`. The query is lowercased, but person fields use case-sensitive `contains` matching. Course-code matching works because it is normalized separately.

### QC-R2-005 — Draft grade leaks through generic student portal

Case: `GRD-006B`
Severity recommendation: Critical

The dedicated `/grades/me` endpoint correctly returned no drafts for a draft-only student. The generic `/portal/view?path=/student/grades` response exposed `Status: draft` for the same student.

## Previously known defects reproduced again

### QC-R2-006 — Student receives people-directory email search results

Case: `SRCH-005`
Severity recommendation: High

A student search for `admin@heritage.edu` returned an admin people-directory result and email address.

### QC-R2-007 — Requested portal path overrides authenticated role

Cases: `PRO-003`, `AUTH-009B`
Severity recommendation: Critical

A student token received HTTP 200 and instructor-role profile data for `/instructor/profile`, and admin-role people data for `/admin/users` through the generic portal API.

### QC-R2-008 — Instructor ownership is not enforced on gradebooks

Case: `GRD-002`
Severity recommendation: Critical

The Pendelton instructor account retrieved the Vance-owned `CS301-01` gradebook and student grades with HTTP 200.

### QC-R2-009 — Score above maximum is accepted

Case: `GRD-003`
Severity recommendation: High

The API accepted a score of 101 against a maximum of 100. The following stale-version case proved optimistic concurrency works, but it does not compensate for the missing score boundary.

### QC-R2-010 — Publish request is not idempotent

Case: `GRD-005`
Severity recommendation: High

Retrying with the same `Idempotency-Key` created two approvals for the same grade item. Database evidence shows one applied approval and one duplicate pending approval.
